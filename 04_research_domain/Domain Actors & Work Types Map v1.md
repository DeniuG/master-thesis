# Domain Actors & Work Types Map v1

**Участники и типы работ предметной области**

Магистерское исследование · системный анализ и управление  
Рабочая версия 1.0

---

# 1. Назначение документа

`Domain Actors & Work Types Map v1` определяет укрупнённые категории участников и типы деятельности, связанные с исследуемыми бизнес-процессами технического обслуживания и ремонта авиационной техники.

Документ является продолжением:

- `Research_Passport`;
- `Research Problem Package v1`;
- `Research Methodology Package v1`;
- `Domain Scope & Boundaries v1`;
- `Glossary v1`;
- `Domain Process Structure v1`.

`Domain Scope & Boundaries v1` устанавливает, что в исследовании должны рассматриваться процессы, связанные с выполнением ТОиР, а также участники, роли и информационные взаимодействия, сопровождающие процесс.

Назначение настоящего документа:

1. определить основные функциональные категории участников;
2. отделить участников от их конкретных должностей;
3. определить основные типы работ;
4. показать связь участников с этапами процесса;
5. определить, какие виды деятельности должны быть исследованы далее;
6. создать основу для последующего `Stakeholder Map` и `RACI`.

Документ **не является организационной структурой конкретного предприятия** и не устанавливает фактическое распределение полномочий.

# 2. Принцип моделирования участников

В рамках исследования различаются четыре уровня:

**Участник → Роль → Тип работы → Конкретная операция**

Например:

**участник**  
планирующая функция

↓

**роль**  
ответственный за планирование

↓

**тип работы**  
планирование сроков и ресурсов

↓

**операция**  
конкретное действие по формированию или изменению плана.

Такое разделение необходимо, поскольку одна и та же организационная единица может выполнять несколько типов работ, а одна и та же работа может выполняться разными участниками в зависимости от конкретного процесса.

---

# 3. Базовые категории участников

На концептуальном уровне выделяются следующие категории:

1. **Управленческая функция**
2. **Планирующая функция**
3. **Инженерная / техническая функция**
4. **Производственно-исполнительная функция**
5. **Контрольная / инспекционная функция**
6. **Материально-техническое обеспечение**
7. **Информационная / системная функция**
8. **Функция качества и соответствия**
9. **Внешний участник процесса**

Последняя категория используется только тогда, когда внешний участник непосредственно взаимодействует с исследуемым процессом или влияет на его выполнение.

# 4. Карта участников

| Категория участника | Основная функция в процессе | Основные типы деятельности | Связь с исследованием |
|---|---|---|---|
| **Управленческая функция** | Приоритизация, принятие решений, контроль состояния процесса | принятие решений, согласование, изменение приоритетов, контроль сроков и результатов | Анализ точек принятия решений и управляемости |
| **Планирующая функция** | Формирование и корректировка плана выполнения | планирование, распределение ресурсов, оценка сроков, перепланирование | Анализ планового и фактического выполнения |
| **Инженерная / техническая функция** | Анализ и техническое уточнение задач | интерпретация требований, уточнение содержания работ, техническая подготовка | Анализ формирования и уточнения задачи |
| **Производственно-исполнительная функция** | Непосредственное выполнение технических работ | выполнение задач, фиксация результатов, передача статуса выполнения | Центральная точка исследования фактического выполнения |
| **Контрольная / инспекционная функция** | Проверка выполнения и результата | контроль, инспекция, подтверждение результата, фиксация несоответствий | Анализ контрольных событий и возвратов |
| **Материально-техническое обеспечение** | Обеспечение процесса необходимыми ресурсами | поиск, резервирование, выдача и перемещение материалов, инструментов и других ресурсов | Анализ зависимостей и ожиданий |
| **Информационная / системная функция** | Поддержка хранения, обработки и передачи информации | регистрация, обработка, интеграция, представление и сопровождение данных | Анализ информационного обеспечения |
| **Функция качества и соответствия** | Контроль соблюдения установленных требований | проверка соответствия, аудит, анализ нарушений и несоответствий | Контекст контроля качества и требований |
| **Внешний участник** | Предоставление внешнего входа, ресурса, решения или услуги | согласование, поставка, техническое взаимодействие, предоставление информации | Учитывается через интерфейс с исследуемым процессом |

# 5. Управленческая функция

## Назначение

Управленческая функция связана с принятием решений, определяющих направление и приоритеты выполнения процесса.

## Основные типы работ

- определение или изменение приоритетов;
- согласование планов;
- принятие решений по отклонениям;
- контроль текущего состояния;
- эскалация проблем;
- подтверждение решений;
- управление исключениями.

## Информационные потребности

Для выполнения таких работ потенциально требуется:

- текущее состояние задач;
- плановые и фактические сроки;
- причины отклонений;
- информация о загрузке;
- информация о зависимостях;
- состояние ресурсов;
- результаты контроля.

Эта категория особенно важна для исследования **своевременности получения информации**.

---

# 6. Планирующая функция

## Назначение

Планирующая функция преобразует требования к выполнению работ в плановый набор действий, сроков и ресурсов.

## Основные типы работ

- формирование плана;
- оценка последовательности;
- планирование ресурсов;
- распределение работ;
- оценка готовности;
- изменение планов;
- перепланирование.

## Особенность для исследования

Планирующая функция является одной из основных точек, где возникают различия между:

**плановым состоянием**

и

**фактическим состоянием**.

Поэтому она непосредственно связана с последующим анализом:

- отклонений;
- своевременности;
- длительностей;
- ожиданий;
- перепланирований.

---

# 7. Инженерная / техническая функция

## Назначение

Инженерная функция обеспечивает техническое понимание и уточнение выполняемой работы.

## Основные типы работ

- анализ технической информации;
- уточнение содержания задачи;
- определение требований;
- интерпретация документации;
- техническая подготовка;
- консультации исполнителей;
- обработка нестандартных ситуаций.

## Роль в исследовании

Функция важна для понимания того, как первоначальная задача превращается в конкретный набор действий.

Она связывает:

**потребность → техническое понимание → планируемую работу → фактическое выполнение.**

---

# 8. Производственно-исполнительная функция

## Назначение

Производственно-исполнительная функция непосредственно реализует техническую работу.

## Основные типы работ

- подготовка к выполнению;
- выполнение технической задачи;
- выполнение отдельных операций;
- фиксация результатов;
- фиксация возникающих проблем;
- передача информации;
- повторное выполнение;
- устранение выявленных несоответствий.

## Роль в исследовании

Это центральная категория для:

- реконструкции фактического процесса;
- событийного анализа;
- анализа состояний;
- анализа временных интервалов;
- анализа возвратов;
- анализа наблюдаемости.

---

# 9. Контрольная / инспекционная функция

## Назначение

Контрольная функция определяет, соответствует ли полученный результат установленным требованиям и может ли задача перейти к следующему состоянию.

## Основные типы работ

- контроль выполнения;
- инспекция результата;
- подтверждение соответствия;
- выявление несоответствий;
- возврат задачи;
- дополнительная проверка;
- подтверждение завершения.

## Роль в исследовании

Контрольные действия являются потенциально важными источниками событий:

**проверка выполнена**

**→ соответствие подтверждено**

или

**→ выявлено отклонение**

**→ возврат на предыдущий этап.**

---

# 10. Материально-техническое обеспечение

## Назначение

Обеспечение выполнения необходимыми ресурсами и материальными объектами.

## Основные типы работ

- определение потребности;
- поиск ресурса;
- проверка наличия;
- резервирование;
- выдача;
- доставка;
- возврат;
- документирование движения ресурса.

## Потенциальное влияние на процесс

Отсутствие необходимого ресурса может приводить к:

**планирование → ожидание → обеспечение → возобновление выполнения.**

Поэтому материально-техническое обеспечение рассматривается не само по себе, а как потенциальный внешний фактор длительности и своевременности процесса.

---

# 11. Информационная / системная функция

## Назначение

Обеспечение информационной поддержки процесса.

## Основные типы работ

- регистрация данных;
- изменение статусов;
- хранение записей;
- передача информации;
- интеграция источников;
- формирование представлений;
- поддержание справочных данных;
- техническое сопровождение информационной инфраструктуры.

## Граница исследования

Информационная система **не является автоматически объектом исследования**.

Она рассматривается как элемент существующего информационного контура процесса.

Поэтому исследуется не:

> «какая система лучше»,

а:

> **какую роль конкретные информационные средства играют в наблюдении, управлении и сопровождении фактического процесса.**

Такой подход соответствует установленной границе, согласно которой внешняя система не становится объектом исследования только потому, что предоставляет данные.

---

# 12. Функция качества и соответствия

## Назначение

Обеспечение соблюдения нормативных, организационных и процедурных требований.

## Основные типы работ

- контроль соответствия;
- аудит;
- проверка документации;
- анализ несоответствий;
- регистрация отклонений;
- участие в корректирующих действиях.

## Роль в исследовании

Функция качества может быть:

- непосредственным участником исследуемого процесса;
- источником evidence;
- потребителем информации;
- внешним контролирующим контуром.

Конкретный вариант должен быть установлен эмпирически.

---

# 13. Внешние участники

Внешними считаются участники, которые не являются частью непосредственной внутренней цепочки выполнения исследуемой работы, но взаимодействуют с ней.

К ним потенциально относятся:

- поставщики;
- подрядчики;
- внешние технические организации;
- внешние экспертные функции;
- регуляторные или контролирующие стороны;
- владельцы или эксплуатанты воздушных судов — в зависимости от фактической организационной модели.

В рамках данного исследования внешний участник включается только при наличии непосредственного интерфейса с исследуемым процессом.

---

# 14. Карта типов работ

Помимо участников необходимо различать **тип выполняемой работы**.

На верхнем уровне выделяются следующие категории:

| Тип работы | Содержание |
|---|---|
| **Инициирование** | Возникновение и регистрация потребности |
| **Аналитическая работа** | Анализ, уточнение и интерпретация задачи |
| **Планирование** | Формирование последовательности, сроков и ресурсов |
| **Обеспечение** | Подготовка необходимых ресурсов и условий |
| **Назначение** | Определение исполнителя и ответственности |
| **Подготовка** | Подготовка рабочего места, документов, ресурсов и условий |
| **Техническое выполнение** | Непосредственная реализация технической работы |
| **Контроль** | Проверка хода и результата |
| **Согласование** | Получение решения, подтверждения или разрешения |
| **Передача информации** | Обмен данными между участниками и источниками |
| **Регистрация результата** | Фиксация события, состояния или результата |
| **Корректирующее действие** | Устранение выявленного отклонения |
| **Повторное выполнение** | Повторное осуществление работы |
| **Перепланирование** | Изменение ранее сформированного плана |
| **Закрытие** | Завершение задачи и фиксация результата |

# 16. Связь участников с укрупнёнными этапами процесса

| Этап | Основные категории участников | Типичные действия |
|---|---|---|
| **1. Возникновение потребности** | инициирующая / управленческая / техническая функция | выявление, сообщение, регистрация основания |
| **2. Регистрация задачи** | информационная / планирующая / инициирующая функция | создание записи, классификация |
| **3. Анализ и уточнение** | инженерная / техническая / планирующая функция | анализ, уточнение, определение условий |
| **4. Планирование** | планирующая / управленческая / техническая функция | сроки, последовательность, ресурсы |
| **5. Обеспечение** | материально-техническая / планирующая функция | подготовка ресурсов |
| **6. Назначение и подготовка** | планирующая / управленческая / исполнительная функция | назначение, подготовка |
| **7. Фактическое выполнение** | производственно-исполнительная / инженерная функция | выполнение, регистрация событий |
| **8. Контроль** | контрольная / качество / техническая функция | проверка, подтверждение, возврат |
| **9. Закрытие** | исполнительная / контрольная / планирующая / информационная функция | фиксация результата, закрытие |

Эта таблица показывает потенциальную логику взаимодействия, но не заменяет последующий анализ фактического процесса.

# 17. Информационные взаимодействия между участниками

В процессе предполагаются следующие классы взаимодействий:

### Управленческая функция ↔ Планирование

**решение / приоритет / план / отклонение / изменение**

### Планирование ↔ Исполнение

**задача / назначение / сроки / план / изменение плана**

### Инженерная функция ↔ Исполнение

**техническая информация / уточнение / результат / проблема**

### Исполнение ↔ Контроль

**результат → проверка → подтверждение / возврат**

### Планирование ↔ Материально-техническое обеспечение

**потребность → ресурс → готовность / отсутствие**

### Все функции ↔ Информационный контур

**регистрация → передача → изменение → получение информации**

Именно эти взаимодействия потенциально формируют значительную часть исследуемой информационной среды.

# 18. Участник как источник и потребитель информации

Для последующего анализа каждый участник должен рассматриваться одновременно как:

**источник информации**

и/или

**потребитель информации**.

Пример:

| Участник | Может создавать | Может использовать |
|---|---|---|
| Планирование | план, срок, назначение, изменение плана | статус задачи, доступность ресурсов |
| Исполнение | факт начала, факт завершения, результат, отклонение | задача, техническая информация, ресурс |
| Контроль | результат проверки, несоответствие | данные о выполнении |
| Инженерная функция | уточнение, техническое решение | исходные сведения о задаче |
| Материально-техническое обеспечение | информация о наличии / выдаче | потребность в ресурсе |
| Управление | решение, приоритет | агрегированное состояние процесса |

Эта схема станет основой будущего `Data & Evidence` и анализа информационного обеспечения.

---

# 19. Участник как источник событий

Не каждое действие участника автоматически является событием.

Событие должно иметь исследовательскую ценность и позволять установить изменение, факт действия или переход.

Потенциальные классы событий:

- задача создана;
- задача назначена;
- задача принята;
- задача начата;
- ресурс запрошен;
- ресурс предоставлен;
- работа приостановлена;
- работа возобновлена;
- результат зафиксирован;
- проведён контроль;
- выявлено несоответствие;
- задача возвращена;
- задача перепланирована;
- задача закрыта.

Конкретный перечень событий должен быть сформирован после анализа реальных источников данных.

---

# 20. Участник и наблюдаемость

Для исследуемой проблемы важно различать:

**участник выполнил действие**

и

**действие наблюдаемо в информационном контуре.**

Возможны ситуации:

**действие произошло → не было зафиксировано**

**действие произошло → зафиксировано с задержкой**

**действие произошло → зафиксировано, но без необходимого контекста**

**действие произошло → зафиксировано в другом источнике**

Поэтому наличие участника в процессе ещё не означает достаточной наблюдаемости его действий.

---

# 21. Участник и своевременность

Для дальнейшего исследования необходимо различать:

**момент выполнения действия**

и

**момент, когда информация о действии стала доступной другому участнику.**

Например:

**исполнитель завершил работу**

→ запись появилась позже

→ планирующий участник увидел изменение ещё позже.

Таким образом, потенциальная исследовательская проблема может находиться не в самом выполнении, а в разрыве между:

**событием → фиксацией → доступностью информации → решением.**

Эта логика непосредственно связана с construct `Timeliness`.

---

# 22. Участник и информационная нагрузка

Информационная нагрузка может возникать в том числе вследствие необходимости:

- переключаться между несколькими источниками;
- вручную сопоставлять записи;
- искать недостающую информацию;
- уточнять состояние задачи через другого участника;
- повторно вводить одни и те же сведения;
- интерпретировать неоднозначные статусы;
- сопоставлять плановые и фактические данные.

Следовательно, для H3 необходимо будет исследовать не только количество информации, но и **сложность информационного взаимодействия участника с процессом**.

---

# 23. Отличие текущей карты от Stakeholder Map

`Domain Actors & Work Types Map v1` отвечает на вопрос:

> **какие функциональные категории участников и какие типы работ существуют в рассматриваемой процессной области?**

Будущий `Stakeholder Map` должен отвечать на другой вопрос:

> **кто именно является заинтересованной стороной исследования, какое имеет отношение к проблеме, какие у неё интересы, потребности, влияние и информационные взаимодействия?**

Поэтому сейчас не фиксируются:

- конкретные фамилии;
- конкретные должности;
- полномочия;
- организационная иерархия;
- степень влияния;
- приоритет заинтересованных сторон.

---

# 24. Отличие текущей карты от RACI

`Domain Actors & Work Types Map v1` определяет:

**кто потенциально участвует и какую работу выполняет.**

`RACI` в дальнейшем должен определять:

**кто Responsible, Accountable, Consulted и Informed для конкретных действий реального процесса.**

RACI нельзя корректно построить до подтверждения фактического AS-IS и реальных ролей.

# 28. Правила дальнейшего уточнения

Новая категория участника включается в модель только тогда, когда:

1. она имеет непосредственную связь с исследуемым процессом;
2. её участие влияет на результат, информацию или ход процесса;
3. участие подтверждается источником либо наблюдением;
4. категория необходима для ответа хотя бы на один RQ.

Новый тип работы включается, если:

1. он представляет самостоятельный класс деятельности;
2. он имеет отношение к исследуемому процессу;
3. его можно отличить от уже существующих типов;
4. его наличие имеет значение для последующего анализа.

# 30. Критерий готовности

`Domain Actors & Work Types Map v1` считается достаточным baseline, когда:

- участники не смешиваются с должностями;
- работы не смешиваются с операциями;
- участники связаны с этапами процесса;
- показаны основные направления информационного взаимодействия;
- определена роль участников в формировании evidence;
- обозначена связь с наблюдаемостью, своевременностью и информационной нагрузкой;
- документ не утверждает фактическую организационную структуру без evidence;
- карта пригодна для дальнейшего построения `Stakeholder Map`, `Process Hierarchy` и `RACI`.

# 32. Граница перехода к следующему этапу

После `Domain Actors & Work Types Map v1` предметная область имеет три базовых уровня:

**Domain Scope**

→ где проходит граница исследования;

**Glossary**

→ каким языком описывается предметная область;

**Domain Process Structure**

→ какие укрупнённые процессные фазы рассматриваются;

**Domain Actors & Work Types**

→ кто участвует и какие классы деятельности выполняются.

Следующий шаг должен уточнить **не роли сами по себе, а структуру иерархии процессов**, чтобы связать участников с конкретными уровнями процесса и выбрать объект для дальнейшей детализации.
